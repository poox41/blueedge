## 2. 今日目标

本次工作集中处理 BlueEdge V1.2.0 原型迁移后的交互一致性、边缘单元上下文切换、概览资源统计准确性，以及边缘资源相关页面的细节问题。在本地完成构建和测试后，仅重新发布本次发生代码变化的前端与 API Gateway，BFF 保持原版本不动。

## 3. 主要修改

### 3.1 表单必填项交互统一

- 新增通用必填项校验工具与 Hook：
  - `frontend/src/lib/form-validation.ts`
  - `frontend/src/hooks/useRequiredFieldValidation.tsx`
- 提交按钮默认保持可点击，不再因为未填写必填项而直接置灰。
- 用户提交时如存在缺失项：
  - 自动定位并滚动到第一个错误字段；
  - 聚焦对应输入控件；
  - 在字段附近显示明确的错误提示；
  - 下拉框、输入框及组合控件采用统一错误状态。
- 已覆盖工作负载、批量工作负载、边缘应用、边缘资源、边云消息等相关创建或编辑流程。

### 3.2 工作负载交互调整

- 去除“工作负载状态”弹窗中的“重启”操作。
- 保留列表操作区的状态/刷新入口，避免误删用户仍需要的列表按钮。
- 列表、详情、创建流程继续沿用真实接口和现有查看、停止等功能。

### 3.3 删除操作规范化

- 一级、二级页面的删除入口统一使用危险操作红色视觉。
- 删除按钮与确认弹窗保持一致的危险语义，减少与普通操作混淆。
- 涉及设备模型、终端设备、节点组、配置项与密钥、权限资源等页面。

### 3.4 列表刷新体验统一

- 含刷新按钮的列表统一增加刷新中动画。
- 刷新结束后再更新表格数据，避免用户误认为按钮无响应。
- 相关页面的刷新逻辑保持真实接口请求，不使用假数据覆盖服务端结果。

### 3.5 边缘单元创建与切换

- 创建边缘单元时暂不要求绑定 `NodeGroup`，与最新业务流程保持一致。
- 工作集群下拉框、版本下拉框的尺寸、箭头位置、弹层宽度和选项样式继续按原型规范统一。
- 修复从边缘单元列表点击“进入工作台”后仍进入上一个边缘单元的问题：
  - 当前边缘单元选择会同步写入上下文；
  - 页面、顶部面包屑和侧边栏卡片使用同一份当前边缘单元数据；
  - 从 `1324141` 进入时不再错误跳转到 `test`。

### 3.6 边缘单元概览统计修复

- 概览卡片不再复用全局或其他边缘单元的统计数据。
- 节点、工作负载、应用实例均按当前边缘单元的数据范围单独统计。
- API Gateway 增强边缘单元资源归属判断：
  - 合并资源标签、资源规格及兼容字段；
  - 兼容已有历史资源的归属信息；
  - 避免顶部卡片与列表/详情数据口径不一致。
- 新增回归测试：
  - `server/api-gateway/test/edge-unit-resource-ownership.test.mjs`
  - 覆盖边缘单元资源归属与统计逻辑。

### 3.7 边缘资源和公共视觉细节

- 边缘资源模块的列表表头背景色统一为页面 `bg` 色，与边缘应用、边云消息模块一致。
- 侧边栏当前边缘单元卡片的尺寸、间距、状态标识和返回按钮统一。
- 节点选择弹窗修复自动聚焦干扰，并统一表头背景、字段、搜索和刷新交互。
- 访问地址列表设置固定内容高度，条目增加后在区域内部滚动，不再持续向下挤压后续内容。
- 外部平台入口按现有 PaaS 跳转方式处理，不在当前平台伪造页面。
- 弹窗继续采用既定尺寸分级：提醒类、轻量编辑、标准长流程、监控/YAML 和抽屉按内容复杂度选型。

```bash

  blueedge-api-gateway=183.95.195.121:31438/blueedge/api-gateway:2026071601 \
  -n blueedge

kubectl set image deployment/blueedge-frontend \
  blueedge-frontend=183.95.195.121:31438/blueedge/frontend:2026071601 \

kubectl rollout status deployment/blueedge-frontend -n blueedge --timeout=240s
```

```bash

```
