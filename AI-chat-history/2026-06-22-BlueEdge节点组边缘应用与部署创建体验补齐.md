# 2026年06月22日 - BlueEdge 节点组、边缘应用与部署创建体验补齐

## 本次对话目标

本次对话继续完善 BlueEdge 前端创建体验，重点处理三个问题：

1. 节点组通过指定节点创建时只能选择一个节点。
2. 创建边缘应用的高级配置与参考页面不一致。
3. 创建部署仍是字段堆叠式弹窗，缺少三步向导、完整容器配置和小尺寸弹窗适配。

本轮改动均位于 `frontend/`，没有修改 BFF、api-gateway 或 Kubernetes/KubeEdge 后端代码。

## 节点组多选修复

### 原问题

节点组表单使用单值字段：

```ts
node: string
```

创建和编辑提交时也只会生成：

```yaml
spec:
  nodes:
    - one-node
```

因此无法在一个节点组中显式选择多个节点。

### 调整结果

- 表单字段改为 `nodes: string[]`。
- 创建和编辑页面均使用复选框列表。
- 支持显示已选择节点数量和一键清空。
- 创建与更新请求直接提交完整的 `spec.nodes` 数组。
- 编辑节点组时只回填 `spec.nodes` 中显式配置的节点，不会把标签选择器动态匹配出的节点误写入 `spec.nodes`。

主要文件：

```text
frontend/src/pages/NodeGroups.tsx
```

## 创建边缘应用调整

### 高级配置页签收敛

原高级配置包含：

```text
节点调度 / 标签与注解 / 访问配置 / 升级策略 / YAML 预览
```

根据参考页面调整为：

```text
标签与注解 / 访问配置 / 升级策略
```

独立的“YAML 创建”入口继续保留，因此删除高级配置中的 YAML 预览页签不会影响 YAML 创建能力。

### 基本信息字段精简

根据后续确认，基本信息中不再展示：

- 节点选择器
- ServiceAccount
- RuntimeClass

目标节点组继续保留，用于生成：

```yaml
spec:
  workloadScope:
    targetNodeGroups:
      - name: edge-group
```

### 升级策略补齐

增加 Deployment `revisionHistoryLimit`，对应页面中的“最大保留版本数”。升级策略当前支持：

- `RollingUpdate`
- `Recreate`
- `maxUnavailable`
- `maxSurge`
- `revisionHistoryLimit`
- `minReadySeconds`
- `progressDeadlineSeconds`
- `terminationGracePeriodSeconds`

主要文件：

```text
frontend/src/components/edge-app/EdgeAppCreateWizard.tsx
frontend/src/components/edge-app/container-model.ts
frontend/src/pages/EdgeApps.tsx
```

## 创建部署三步式改造

创建部署从原来的单弹窗表单改为与创建边缘应用一致的三步式向导：

```text
1. 基本信息
2. 容器配置
3. 高级配置
```

同时继续保留独立的 YAML 创建模式。

### 第一步：基本信息

支持：

- 负载名称
- 负载别名
- 命名空间
- 实例数
- 描述

负载别名和描述通过 BlueEdge 注解写入 Deployment：

```yaml
metadata:
  annotations:
    blueedge.io/alias: example
    blueedge.io/description: example description
```

### 第二步：容器配置

容器配置补齐为可折叠的分组结构，当前支持：

- 容器名称和镜像
- `imagePullPolicy`
- 镜像仓库 Secret
- 特权容器
- CPU requests/limits
- 内存 requests/limits
- GPU 扩展资源 `nvidia.com/gpu`
- 容器端口
- command/args
- `postStart` 与 `preStop`
- liveness/readiness/startup HTTP 检查
- `env` 环境变量
- PVC、卷名称、挂载路径和子路径
- `runAsUser`
- `runAsNonRoot`
- `readOnlyRootFilesystem`
- `allowPrivilegeEscalation`

以上字段由表单生成真实 Deployment 容器结构，不是仅用于展示。

### 第三步：高级配置

高级配置包含四个页签：

```text
节点调度 / 标签与注解 / 访问配置 / 升级策略
```

节点调度支持：

- 自动调度
- `nodeName` 指定节点
- `nodeSelector` 标签匹配
- tolerations 容忍配置

访问配置支持：

- 不暴露主机端口
- `hostPort` 端口映射
- `hostNetwork` 主机网络

升级策略支持：

- `RollingUpdate` / `Recreate`
- `maxUnavailable`
- `maxSurge`
- `revisionHistoryLimit`
- `minReadySeconds`
- `progressDeadlineSeconds`
- `terminationGracePeriodSeconds`

### 弹窗尺寸和响应式修复

创建部署弹窗最终与创建边缘应用使用相同尺寸，不再强制占满浏览器窗口。

缩小弹窗后曾出现高级配置右侧被裁切，原因是内部仍使用固定的：

```text
180px + 520px
```

双栏宽度。后续已改为响应式布局：

- 四个高级配置页签等宽显示。
- 表单右栏使用 `minmax(0, 1fr)`。
- 调度方式允许自动换行。
- 标签、注解、容忍和升级字段不会横向溢出。

主要文件：

```text
frontend/src/components/deployment/DeploymentCreateWizard.tsx
frontend/src/pages/Deployments.tsx
```

## 表单与 YAML 的真实接口链路

本轮对四条创建路径进行了代码级审计。

### Deployment

```text
表单创建
  -> buildDeploymentResource(form)
  -> POST /product-api/bff/deployment/{namespace}

YAML 创建
  -> YAML 解析与 kind/name 校验
  -> POST /product-api/bff/deployment/{namespace}
```

### EdgeApplication

```text
表单创建
  -> buildEdgeApplicationResource(form)
  -> POST /product-api/bff/edgeapplication/{namespace}

YAML 创建
  -> YAML 解析与 EdgeApplication 结构校验
  -> POST /product-api/bff/edgeapplication/{namespace}
```

完整运行链路为：

```text
frontend
  -> /product-api/bff
  -> blueedge-api-gateway
  -> 官方 kubeedge-dashboard BFF /api/v1
  -> Kubernetes API / KubeEdge EdgeApplication CRD
```

这四条路径均调用真实资源创建接口，不使用前端 mock 数据。

需要注意，代码链路打通不等于任意环境都一定创建成功。运行环境仍需满足：

- 前端新版本已经重新构建并部署。
- BFF 可以正常访问 Kubernetes API Server。
- 创建边缘应用时，集群已安装 EdgeApplication CRD 和对应控制器。
- 目标节点组、PVC、Secret 等引用资源真实存在。
- 提交的 YAML 符合 Kubernetes/KubeEdge 资源规范。

本次只完成代码级接口审计，没有为了验证而向当前集群实际 POST 创建测试资源。
