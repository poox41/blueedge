### 4.1 创建私有仓库拉取凭证

Secret 必须创建在 `blueedge` 命名空间。密码不要直接保存进仓库文件：

```bash
kubectl create secret docker-registry blueedge-registry-secret \
  -n blueedge \
  --docker-server=183.95.195.121:31438 \
  --docker-username=adminn \
  --docker-password='<仓库密码>' \
  --dry-run=client -o yaml | kubectl apply -f -
```

让三个 Deployment 使用该 Secret：

```bash
for name in blueedge-frontend blueedge-api-gateway blueedge-bff; do
  kubectl patch deployment "$name" -n blueedge \
    -p '{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"blueedge-registry-secret"}]}}}}'
done
```

服务器此前已为 containerd 配置 `183.95.195.121:31438` 的证书跳过校验。如果再次出现证书错误，应检查：

```text
/etc/containerd/certs.d/183.95.195.121:31438/hosts.toml
/etc/containerd/config.toml
```

其中 containerd 的 registry 配置目录应为：

```toml
config_path = "/etc/containerd/certs.d"
```

## 八、异常排查

### 8.1 ImagePullBackOff 或 ErrImagePull

```bash
kubectl get pods -n blueedge
kubectl describe pod -n blueedge <Pod名称>
kubectl get secret blueedge-registry-secret -n blueedge
```

重点检查：

- 镜像 tag 是否真实存在。
- `blueedge-registry-secret` 是否位于 `blueedge` 命名空间。
- Deployment 的 `imagePullSecrets` 是否引用该 Secret。
- containerd 是否配置私有仓库 `skip_verify`。
- 服务器是否能访问 `183.95.195.121:31438`。

### 8.2 CrashLoopBackOff

```bash
kubectl logs -n blueedge <Pod名称>
kubectl logs -n blueedge <Pod名称> --previous
```

## 十、持久化部署配置

`kubectl set image` 会立即更新线上 Deployment，但不会自动修改本地 YAML。确认线上版本正常后，应同步更新：

```text
deploy/k8s/blueedge/10-bff.yaml
deploy/k8s/blueedge/11-api-gateway.yaml
deploy/k8s/blueedge/12-frontend.yaml
```

否则后续重新执行：

```bash
kubectl apply -k deploy/k8s/blueedge
```

可能会把线上镜像重新覆盖为 YAML 中记录的旧版本。
