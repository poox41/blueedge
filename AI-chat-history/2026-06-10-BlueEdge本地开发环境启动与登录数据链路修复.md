## 登录成功但不跳转

现象：

- `/product-api/auth/login` 返回 `200`
- 页面仍回到登录页
- DevTools 里能看到后续 `node/deployment/cluster/events` 请求返回 `401/503`

原因：

前端通用请求层之前把任意接口的 `401` 都视为登录失效，会清理 `blueedge_token` 并强制跳回 `/login`。

但登录后首页会立刻请求 BFF 资源接口，例如：

```text
/product-api/bff/node
/product-api/bff/deployment
```

这些资源接口的 `401` 不等于 BlueEdge 平台 JWT 失效，只能说明 BFF/Kubernetes 数据链路没有凭证或无权限。

修复：

```text
frontend/src/api/request.ts
```

只在 gateway 平台鉴权接口返回 `401` 时清理登录态，不再让 BFF 资源接口的 `401` 把用户踢回登录页。

验证：

```bash
cd frontend
npm run build
```

构建通过。

## 首页数据为空与资源接口 401/503

现象：

- 页面能登录并进入首页
- 节点、部署、设备等数据为空
- DevTools 中资源接口大量 `401`
- metrics 接口显示 `system:anonymous` 无权限

原因：

BlueEdge 登录 JWT 只用于平台登录态；官方 BFF/Kubernetes 资源访问需要服务端 Kubernetes 凭证。

本地 gateway 启动时 `K8S_TOKEN` 为空，因此 gateway 转发到官方 BFF 或 Kubernetes API 时没有 Kubernetes 身份，最终被集群识别为 `system:anonymous`。

处理：

- 通过远端集群生成开发用 Kubernetes ServiceAccount token
- 不把 Kubernetes token 暴露到浏览器
- 仅注入本地 `api-gateway` 的 `K8S_TOKEN` 环境变量
- 重启本地 gateway

验证接口：

```text
/bff/node -> 200
/bff/deployment -> 200
/metrics/cluster -> 200
```

## 部署列表搜不到 yaml-test-nginx

现象：

- 在部署页面用 YAML 创建 `yaml-test-nginx`
- 再次创建时报：

```text
deployments.apps "yaml-test-nginx" already exists
```

- Pods 页面能看到：

```text
yaml-test-nginx-76597bf999-tj6rf
```

- 但部署页面搜索 `yaml-test-nginx` 显示 0 条

排查结果：

直接请求单个 Deployment 能拿到资源：

```text
GET /bff/deployment/default/yaml-test-nginx -> 200
```

请求 default 命名空间列表也包含：

```text
default/yaml-test-nginx
```

真实原因：

部署页原来在“全部命名空间”下只请求官方 BFF 默认第一页：

```text
GET /deployment
默认 pageSize = 20
```

然后前端只在这 20 条里做本地搜索。`yaml-test-nginx` 不在第一页，所以搜索结果为 0。

修复：

```text
frontend/src/api/services/resources.ts
frontend/src/pages/Deployments.tsx
```

调整内容：

- 新增 `listDeploymentPage(...)`
- 支持 `page/pageSize/filter/sort/order`
- 部署页改为 BFF 服务端分页和服务端名称搜索
- “共 N 条”使用 BFF 返回的真实 `total`

验证：

```text
GET /bff/deployment?page=1&pageSize=10&sort=creationTimestamp&order=desc&filter=name:*yaml-test-nginx*
```

返回：

```text
total: 1
items: default/yaml-test-nginx
```

前端构建通过。

## 后续注意事项

- 本地开发时如果页面资源接口为空，先检查 `K8S_TOKEN` 是否注入到 gateway。
- 浏览器里只保存 BlueEdge 平台 JWT，不保存 Kubernetes token。
- 部署列表是 Kubernetes 原生 Deployment 列表；Pod 页面看到的是 Deployment/ReplicaSet 拉起的 Pod。
- 官方 BFF 列表接口默认分页，前端搜索如果要覆盖全集，应使用服务端 `filter`，不要只搜本地第一页。
- 本地开发进程如果通过普通 `nohup` 启动后很快消失，可继续使用 `launchctl` 托管。
